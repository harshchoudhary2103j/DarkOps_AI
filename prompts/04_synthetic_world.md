# Phase 04 — Synthetic World

## Objective
Implement the deterministic Synthetic World Seeder in Python within `services/simulation-worker` to generate reproducible quick-commerce dark stores, catalogs, warehouse shelf layouts, initial stock positions, and historical sales data.

## Scope
- Implement the World Seeder module:
  - Configurable seed parameters (e.g., number of stores, SKU catalog size, warehouse dimensions, supplier count, random seed integer).
  - Virtual store generator: geographic locations, service polygon boundaries, operating hours.
  - SKU & catalog generator: category distribution, pack sizes, perishable shelf life profiles, storage requirements, pricing.
  - Warehouse layout generator: aisles, shelves (X, Y, Z coordinates), dispatch stations, navigation graph edges.
  - Initial stock & supplier generator: starting physical stock per SKU/store, supplier lead times, and initial purchase order schedules.
  - Historical sales generator: 14-30 days of pre-warmed sales history to seed baseline demand forecasting.
- Expose an export adapter that formats seeded data into standard Operational API payload schemas and populates the database via normal API endpoints.

## Dependencies
- Phase 01: Domain Contracts and Persistence (Catalog schemas).
- Phase 02: Inventory Core (Stock initialization interfaces).

## Business & Engineering Invariants
- Determinism: Given the same random seed and configuration file, the World Seeder must produce byte-for-byte identical catalogs, layouts, stock distributions, and historical sales.
- Generated records must conform strictly to standard domain models; the seeder must not bypass foreign keys or create orphan shelf coordinates.
- The seeder generates initial operating conditions; it must never invent operational metrics or performance KPIs.

## Acceptance Criteria
1. Seeding with seed `42` executed twice generates identical store coordinates, SKU counts, shelf graphs, and historical sales data.
2. Warehouse graphs generated by the seeder are fully connected and traversable from the packing station to all shelf nodes.
3. Seeded operational data successfully imports into the Operational API through standard catalog endpoints without schema or foreign key errors.

## Required Tests
- Determinism tests: running the generator twice with identical seeds produces identical JSON outputs (`hash(runA) == hash(runB)`).
- Graph validation tests: verifying connected components and path existence in generated warehouse layouts.
- Schema conformity tests: validating that seeded outputs match Pydantic and Zod catalog schemas.
